## 参与者和space

ASP有两端。**space**是一个世界：它持有或接入一个状态，执行自己的定律，保存记录，推送事件。**参与者**进入一个space并在里面行动。agent和人都是参与者；区分它们的是space给的角色，不是协议。

| 部分 | 是什么 | 例子 |
| --- | --- | --- |
| 参与者 | 用SDK进入一个space并在里面行动的任何东西 | 任何框架写的agent，比如The Harness；一段脚本 |
| space | 有状态、定律和参与者的世界 | 有机器人的家、虚拟房间、群聊、项目文件夹、游戏服务器、评测环境 |
| 宿主 | 用户运行的应用，把agent连上space，并嵌入space自带的界面；和MCP里的host同义 | 桌面agent应用、IDE、网页 |
| 客户端 | 按自己认识的形式把space呈现给人的参与者 | inspector的终端客户端 |

有些参与者在协议外：真实桌面前的人，有机器人的房间里的人，没经ASP接入的群友。他们做的事以事件出现，起因标为外部。

## 两种space

space要么自己**持有**状态，比如由引擎运行的房间和牌局；要么接入**外部**的状态，比如机器人控制器和传感器、项目文件夹、桌面或聊天平台的适配器。两种都说同一个协议，通过同样的一致性测试；适配器只报告外部系统确认过的东西，确认不了就说"不确定"。

## 一次连接

1. 双向的**hello**：space发出自己的身份、每一部分支持的版本、能力和词汇的哈希；参与者回自己的密钥、证明和版本。每部分取双方都支持的最高版本。
2. **join**开始一次在场，带角色，也可以带呈现偏好。
3. **observe**和**subscribe**：先取这个角色能看到的投影，再从某个序号起订阅事件。
4. **act**和**edit**：各带一个ID，最后恰好得到一个**outcome**。
5. **leave**结束这次在场。

消息是JSON，走WebSocket、带服务器推送事件的HTTP，或者标准输入输出。见[消息](../../../specification/v0/messages/)和[传输和身份](../../../specification/v0/transports/)，各个术语见[术语](../terminology/)。
