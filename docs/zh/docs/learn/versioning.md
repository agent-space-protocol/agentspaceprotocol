ASP是整个系统里要长期稳定的部分：agent、space和客户端只要还说这个协议，随时可以重写。所以它只做加法。

## 部分和版本

协议分成几部分：核心，以及每项能力各一部分。每部分有一个整数版本。在`hello`里，space列出每部分支持的版本，参与者回自己的；每部分取双方都支持的最高版本，没有交集的部分就是不支持。简单的space和复杂的space说的是同一个协议，不需要一个全局的版本号。

## 兼容的规矩

1. 读不懂的字段要忽略，转发时原样保留。
2. 字段、消息、动词、结果、原因和事件的名字永不改名、不改义、不复用。
3. 新实现读所有旧版本的数据，只写当前版本。
4. 每个扩展都带命名空间。
5. 词汇的包按大版本区分，同一个大版本里只加不改。

见[协商和兼容](../../../specification/draft/compatibility/)。

## 草案和发布

协议还是草案时，每部分都是版本`0`，[specification/draft](../../../specification/draft/)里的正文还可能改。等真实的环境通过一致性测试，各部分冻结，之后每一版正文都留在一个按日期的地址上，和MCP一样。
